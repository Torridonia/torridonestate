Torridonia Operations Guide

torridonia.com · September 2026 · Internal reference — Felix & Jorge

Welcome, Felix

This guide is your complete reference for running and maintaining the Torridonia digital platform. You will find step-by-step access instructions for every tool, a map of the website, and a private credentials vault that only you and Jorge can access.

The single most important thing: for day-to-day management — rooms, photos, volunteer rota, page text — you only need the Admin Panel at torridonia.com/admin. The other platforms require technical help to use safely.

Updating the Website Content

Changing page text

Go to Admin → Pages (torridonia.com/admin/pages). Select the page. Each paragraph or heading is a simple text box — type, save, done. Changes go live immediately with no deploy.

Changing room photos

Go to Admin → Spaces (torridonia.com/admin/spaces), then click the room. In the Media section, click Upload, pick a photo, done. Drag tiles to reorder. Bin to delete.

Managing the volunteer rota

Go to Admin → Volunteers (torridonia.com/admin/volunteers). Navigate weeks with Prev / Next. Each cell has a dropdown to assign a shift. Click the star to mark a lead.

For developers

Deploying Code Changes

Deploying is automatic. When a developer pushes code to the main branch on GitHub, Vercel picks it up and the website updates within 2–3 minutes. No manual step required. Felix does not need to do this.

If something looks broken after a deploy, open vercel.com (via GitHub login) and check the latest deployment. Green = live, Red = call Jorge.

Critical rules

Security Rules

  • !
    Never share the Supabase service key with anyone outside Jorge and a developer. This key has full database access. It lives only on the server — never in an email or on a computer desktop.
  • !
    The admin password for bookings@torridonia.com is the master key. If this password is compromised, change it immediately in Google Workspace and notify Jorge — it will lock everything out of GitHub and Cloudflare automatically.
  • !
    A booking is only confirmed when the guest pays — never manually. Do not mark a booking as "Confirmed" in the admin panel by hand. Only the payment webhook does this. This protects against double-bookings.
  • ✓
    Volunteers cannot access admin functions. Volunteers sign in at /staff/login and see only their rota and SOPs. Their account gives them zero access to the admin panel, bookings, or financial records.
  • ✓
    The database is locked to anonymous access. Even if the admin link were shared publicly, the database refuses all requests that don't carry a verified login. There are no public holes in the data layer.
